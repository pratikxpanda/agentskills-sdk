    OCI provider

    Artifact Layout¶

    Each skill is an OCI artifact addressed by a tag matching the skill ID. The manifest must use application/vnd.agentskills.skill.v1 as artifactType and the same skill ID in org.opencontainers.image.title. Each canonical file is a raw layer using application/vnd.agentskills.file.v1; its title annotation contains the relative POSIX file path. The provider reads manifests during discovery and fetches file blobs only when requested.

    Usage¶

    pip install agentskills-oci

    The repository must already contain artifacts in the required format. The package guide has a runnable async reader and the full artifact-field contract. The package is read-only and does not turn arbitrary container images into skills.

    ORAS uses its token auth backend and local Docker-compatible credentials by default. Pass a configured ORAS client for other registry authentication or TLS settings. Layer digests establish byte consistency. Use the core trust policy after capturing a complete skill snapshot when publisher verification is required.

    API Reference¶

    agentskills_oci.OCISkillProvider ¶

    Bases: SkillProvider

    Read skills from OCI artifacts without pulling unrelated file content.

    Each skill is one tag in the configured repository. Its OCI image manifest uses artifactType application/vnd.agentskills.skill.v1 and stores each canonical file as a raw layer. The standard org.opencontainers.image.title layer annotation contains the POSIX path relative to the skill root. The same annotation on the manifest must match the skill tag.

    ORAS authentication and TLS settings remain registry-owned. By default, ORAS uses its token auth backend and local Docker-compatible credentials. A configured ORAS client can be injected for other registry controls. File descriptor digests are verified when blobs are read; publisher signatures remain host-verified through agentskills-core trust policies.
