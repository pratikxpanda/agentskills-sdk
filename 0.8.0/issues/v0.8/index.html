    v0.8 Portable Distribution

    Scope and Release Contract¶

    v0.8 adds reproducible Git sources, offline lock verification, framework-neutral MCP consumption and client-side composition, an optional MCP prompt, Azure Blob Storage, and OCI Distribution. The release contains eleven lockstep packages. Additional object stores and server-side MCP federation remain demand-gated and are not part of this milestone.

    This specification defines the observable contracts for the current implementations. A registry digest establishes byte consistency. Publisher identity is established only when a host applies the core trust policy to a complete captured snapshot. Approval, skill selection, session lifecycle, and execution remain host-owned.

    Git Provider¶

    • Resolve a branch or tag once to an immutable commit and expose the resolved SHA.
    • Support a repository-relative subdirectory and complete byte-preserving skill files.
    • Bound per-checkout and total cache size with LRU eviction and cross-process leases.
    • Disable repository hooks, system/global Git configuration, submodules, and external protocols.
    • Never execute skill scripts.
    • Pass the shared provider conformance suite and test mutable refs, cache contention, eviction, and unsafe repository content.

    Lockfile and Offline Verification¶

    • agentskills lock create records the repository, requested ref, resolved commit, and canonical per-file SHA-256 manifest.
    • agentskills lock update refreshes a moved ref while retaining a reviewable prior lockfile revision in version control.
    • agentskills lock verify performs no network access and checks the origin, resolved commit, clean worktree, canonical file inventory, and bytes read from Git objects.
    • Detect missing, modified, ignored, and untracked files without normalizing file bytes through the worktree.
    • Keep the lockfile tied to the existing skill manifest format rather than defining another content schema.

    MCP Consumption and Composition¶

    • Use the official MCP client SDK for paginated Skills discovery, direct URI lookup, and on-demand resource reads.
    • Verify fetched resource size and digest against the manifest and preserve identity as (origin, URI).
    • Compose clients only when caller-assigned origins are unique. Route each lookup and read to the originating session, including when two origins publish the same URI.
    • Do not rehost or forward content from the collection. This avoids server-side forwarding loops by construction.
    • Keep transport, sessions, approval, selection, and execution with the host.
    • Keep the use-skill prompt disabled by default. It is user-invoked, resolves a canonical URI, and grants no tool permissions.
    • Do not add framework lifecycle adapters or server-side federation in v0.8. These require separate demand and acceptance criteria.

    Azure Blob Provider¶

    • Install Blob support with agentskills-azure[blob] and import AzureBlobSkillProvider from agentskills_azure.blob. The base Azure namespace does not load service SDKs.
    • Use the asynchronous Azure Blob SDK and DefaultAzureCredential by default, with optional caller-supplied async credentials.
    • Close provider-owned service and credential clients while leaving injected credentials under caller ownership.
    • Support discovery, standard resource listing, complete file listing, and on-demand reads beneath an optional container prefix.
    • Preserve original file bytes, reject unsafe paths, and enforce per-file size limits while downloading.
    • Pass the shared provider conformance suite using isolated fake clients. Real identity assignment and cloud authorization remain deployment responsibilities.

    Azure Files Provider¶

    • Install agentskills-azure[files] and import AzureFilesSkillProvider from agentskills_azure.files independently of the Blob extra.
    • Use the async FileREST SDK for SMB shares beneath an optional directory prefix. Reject NFS shares and reparse points.
    • Require explicit token_intent="backup" acknowledgement for token authentication. Document ACL bypass and the required Azure RBAC permissions.
    • Discover skill directories and list nested files without downloading their contents. Preserve original bytes with automatic decompression disabled.
    • Reject unsafe paths and enforce streamed file-size, file-count, and directory-depth limits.
    • Close owned clients and credentials while preserving caller-owned credentials, including when client cleanup fails.
    • Pass the shared conformance suite using fake clients. Production identity and share authorization remain deployment responsibilities.

    OCI Distribution Provider¶

    • Address each skill by a valid skill-ID tag in one configured OCI repository.
    • Require application/vnd.agentskills.skill.v1 as the artifact type and a manifest title matching the tag.
    • Represent every canonical file as one raw layer using application/vnd.agentskills.file.v1; the standard OCI title annotation carries its relative POSIX path.
    • Read tags and manifests for discovery and listing without fetching file layers. Fetch each layer only when its path is requested.
    • Reject unsafe or duplicate paths, unsupported media types and digests, invalid sizes, missing SKILL.md, and file-count or total-size limit violations.
    • Verify the streamed layer byte count and SHA-256 digest against the descriptor before returning bytes.
    • Use ORAS registry authentication and TLS controls. Keep TLS verification enabled by default, and leave injected client configuration with the caller.
    • Do not imply that a registry signature or digest alone establishes publisher trust. Hosts may verify the complete captured snapshot with the core trust policy.
    • Pass the shared provider conformance suite using a fake registry client. Production registry credentials and authorization remain deployment responsibilities.

    Release Gates¶

    • Keep all eleven package versions and internal dependency floors aligned for the release tag.
    • Pass tests on Python 3.12, 3.13, and 3.14, every package coverage floor, and the aggregate coverage floor.
    • Pass Ruff lint and formatting, declared-dependency checks, poetry check --lock, and strict MkDocs generation.
    • Build all eleven distributions in dependency order and verify the release tag against every package manifest.
    • Retain the current release process for Trusted Publishing and attestations.

    Local fake-client tests validate the package contracts. They do not certify a production cloud identity configuration, registry policy, host approval flow, or publisher key distribution.
